# Minitest 6 implementation plan

> **For agentic workers:** Use superpowers-ruby:subagent-driven-development with Luna implementers and independent spec then quality reviews. One implementation writer at a time; parent owns commits and delivery.

**Goal:** Support Minitest 6 serial applications without regressing Minitest 5.

**Architecture:** Preserve stable lifecycle hooks, update version and runner
safety checks, and prove compatibility through a versioned consumer test matrix.
Keep the normal development bundle and full-suite runner on Minitest 5.

**Tech stack:** CRuby 4.0, Minitest 5/6, Ruby standard library, existing RBS and CI.

## Task 1: Adapter and diagnostic compatibility

Files: `lib/branchproof/minitest_adapter.rb`, `lib/branchproof/doctor.rb`,
`test/test_minitest_adapter.rb`, `test/test_worker.rb`, `test/test_doctor.rb`,
and affected missing-framework assertions in `test/test_optional_frameworks.rb`.

- [x] Write failing tests accepting 6.0.0/6.0.6, rejecting 5.25.4/7.0.0, retaining
  activated-metadata precedence, recognizing `run_order == :parallel`, and
  rejecting bisect/server switches or active server mode before bodies execute.
- [x] Record RED with the existing `< 6` guard and unsupported scheduling check.
- [x] Widen adapter/doctor range to `Gem::Requirement.new(">= 5.25.5", "< 7")`.
  Preserve existing lazy loading and diagnostic codes. Extend scheduling checks
  to inspect both generation-specific order APIs, preserving module checks.
- [x] Extend unsupported runner checks for `--bisect`, `-b`, server options and
  active server integration, using upstream behavior to avoid false positives.
- [x] Run focused adapter, worker, doctor, optional-framework tests and lint.
- [x] Resolve Luna spec review followed by quality review.

Task 1 evidence: initial adapter RED had 9 runs, 3 failures, and 1 error.
Default-bundle GREEN: adapter 10/41, worker 26/90, doctor 14/78, doctor
acceptance 7/142, packaged optional frameworks 1/76 (runs/assertions), all
without failures or errors. Adapter also passed 10/41 under actual Minitest
6.0.0. Seven changed Ruby files passed RuboCop. Independent Luna spec and
quality reviews passed. `MINITEST_SERVER` is used by Minitest 6.0.6; the
6.0.0 server plugin instead relies on its runner option.

## Task 2: Real consumers and CI matrix

Files: `Gemfile`, `.github/workflows/main.yml`, new
`test/test_minitest_compatibility.rb`, and existing CLI/doctor/packaging
acceptance files where their meaningful assertions need adaptation.

- [x] Add a version selector while retaining the default locked Minitest 5 band:

  ```ruby
  if ENV["BRANCHPROOF_MINITEST_VERSION"]
    gem "minitest", ENV.fetch("BRANCHPROOF_MINITEST_VERSION")
  else
    gem "minitest", ">= 5.25.5", "< 6"
  end
  ```

- [x] Add real temporary project tests for lifecycle ownership/counts, seed and
  filtering parity, Minitest 6 scheduling, unsupported server/bisect/custom modes,
  and successful tests with both failing and passing MC/DC gates. Use
  `RbConfig.ruby`/`Open3.capture3`, explicit child dependency selection, and
  marker files proving rejected modes did not execute test bodies.
- [x] Reuse existing CLI acceptance for failures/skips/empty runs and doctor /
  installed-consumer acceptance. Avoid tests that depend on Minitest mocks in
  the Minitest 6 lane.
- [x] Resolve each exact framework version in a separate bundle environment or
  sequentially restore the base lockfile after validation. Assert activated
  version matches the requested version; do not silently fall back to 5.
- [x] Add dedicated CI version jobs for 5.26.2, 6.0.0, and 6.0.6 using the selector,
  `BUNDLE_FROZEN=false`, `bundle update minitest`, then the bounded adapter/CLI/
  lifecycle/doctor/packaged-consumer acceptance set. Existing core/full-suite and
  Rails jobs retain their default Minitest 5 selection.
- [x] Run focused tests and lint; resolve independent Luna spec/quality reviews.

Matrix adjustment: installing Minitest 5.25.5 on Ruby 4.0.1 failed because its
published gem requires Ruby `>= 2.7, < 4.0`. Use 5.26.2 (Ruby `>= 3.1`) for
the additional Minitest 5 lane; retain the existing adapter lower-bound
check and locked 5.27.0 full suite. Do not bypass upstream Ruby requirements.

Task 2 evidence: both real Minitest 6 runs initially exposed duplicate Prism
staging in the installed-consumer fixture. Sharing its visited dependency set
fixed that failure. The bounded acceptance matrix then passed 42/432 on 5.26.2
and 42/450 on both 6.0.0 and 6.0.6. After adding default discovery, the final
compatibility file passed 7/59 on both 5.26.2 and 5.27.0, and 7/71 on both
6.0.0 and 6.0.6. Workflow parsing, bundle checks, scoped lint, and independent
Luna spec/quality reviews passed. The repository lockfile remains unchanged.
